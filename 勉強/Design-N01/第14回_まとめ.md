# Webデザインの制作フロー
## Webサイト制作の中での位置
要件定義 → **デザイン** → コーディング → リリース
- Webデザインは要件定義の後に行う

## デザインの3工程
| 工程 | 役割 | 成果物 |
| --- | --- | --- |
| ラフスケッチ | デザインのアイデアを出す（デザインの原点） | Webサイトの下書き |
| ワイヤーフレーム | サイトの構成・レイアウトを決める（ラフスケッチの清書） | Webサイトの設計図 |
| デザインカンプ | デザインの完成形を作る（モックアップとも呼ぶ） | 納品データ・コーディングの元データ |

- 工程をすべて終えてからではなく、工程ごとに細かくフィードバックをもらうと、後戻りが少なく済む
- 📎 [Webデザインの制作の流れ](https://zero-plus.io/media/flow-of-web-design/#i)（上流工程のOKをもらったら、読んでからラフスケッチに進む）

## ラフスケッチ
- 紙とペンで描く（デザインツールより速い）
- 綺麗さは気にしない。思いついたことはメモしておく
- 案を多く出し、抽象的なラフから具体的なラフへ描き換えて、完成イメージを膨らませる

## ワイヤーフレーム
- 「どこに何を置くか」を決めた設計図
- 基本は白黒で作る
    - 色や画像を先に入れると、次の工程で自由な発想が生まれにくくなるため
- 画像が入る場所には灰色の四角形を置く
- ダミーテキストは完成に近い文章で打ち込む
- テキストのスタイル（サイズ・行間・字間）を決めておく
- 余白や大きさは8の倍数で決める
- 打ち合わせの資料にもなる

## デザインカンプ
- 灰色の四角形に本番用の画像を入れる
- ベース・メイン・アクセントの3色で配色する
- あしらい（装飾）を加え、対比でメリハリをつける
- 誤字脱字をチェックする（作った直後ではなく、時間を空けて確認する）

# デザイン4原則
デザインで遊ぶための前提となるルール。

| 原則 | 意味 | 目的 |
| --- | --- | --- |
| 近接 | 似ている情報を近くにまとめる | 情報を整理しやすくする。余白の広さを決める手助けになる |
| 整列 | 基準を決めて要素を揃える | 統一感を出し、見やすく綺麗にする |
| 反復 | 要素の見た目を繰り返し使う | 情報をグループにまとめ、統一感を与える。視認性・可読性が上がる |
| 対比（強弱） | 要素の見た目にメリハリをつける | 情報の優先順位を明確にし、強調したい要素を伝える |

## 近接
- 関係のある情報は近くに、異なる情報は遠くに置く
- ポイントは「余白」
- 例：「画像」「文章説明」「リンク」の3グループの間に広い余白をとると、グループが分かれて見える
- 余白の大きさがバラバラだと、どれとどれがセットなのか伝わりにくい。余白のルールを決めて使い分けると、見る人が情報のまとまりを自然に読み取れる（「デザインルールの例」参照）

## 整列
- 揃っていないと、ガタガタした印象になり、情報が少なくても読みにくくなる
- 例：ナビゲーションやキャッチコピーの端を揃える

## 反復
- 内容が違っても見た目を揃えると、全部読まなくても同じグループだと分かる
- 例：カリキュラムの3項目で、見出し・文章の見た目を統一する

## 対比（強弱）
- コントラスト（視覚的な特徴の差）で、伝えたいものを強調する
- 例：キャッチコピーのフォントサイズを大きくする、問い合わせボタンにアクセントカラーを使う
- 集客が目的のサイトでは、重要なボタンを目立たせることが求められる

# レイアウトパターン
## カラムを使ったレイアウト
カラム＝縦の列のこと。

| レイアウト | 特徴 | 向いているサイト |
| --- | --- | --- |
| ワンカラム | 縦一直線に配置。内容に集中しやすく、ストーリー性を持たせやすい。レスポンシブと相性が良い | ランディングページ |
| 2カラム | メインとサイドバーなど2列で構成。多くの情報を見せられる | ECサイト、ブログ |
| 3カラム | 3列に分割。情報量を増やせ、回遊性を高められる | ニュースサイト |
| マルチカラム | 2カラム以上をページ内で組み合わせる。他ページへの導線を見せやすい | 情報量の多いコーポレートサイト、メディアサイト |

## グリッドを使ったレイアウト
グリッド＝同じ大きさの正方形・長方形で画面を方眼状に分割したもの。

| レイアウト | 特徴 | 向いているサイト |
| --- | --- | --- |
| グリッド | 情報を整理しやすく、一度に多く見せられる。レスポンシブと相性が良い | Webデザインの基本的な方法 |
| カード・タイル | グリッドの一種。画像を敷き詰めて一覧表示する | 画像や情報が多いサイト |
| ブロークン・グリッド | グリッドをあえて崩して自由に配置する。オリジナリティが出て視線を惹きつけるが、レスポンシブ・コーディングの難易度が高い | ポートフォリオ、イベントサイト |

- 📎[SANKOU](https://sankoudesign.com/) などの参考サイトで、実際のレイアウトを確認する

# Figmaの基本
## Figmaとは
- WebサイトやWebアプリの見た目（UIデザイン）を作るデザインツール
- ブラウザで使える（デスクトップアプリもある）
- 無料のStarterプランでも、制作は進められる

## 画面構成
| 場所 | 役割 |
| --- | --- |
| キャンバス | オブジェクトを配置してデザインを作る作業領域 |
| ツールバー | ツールの切り替え、ファイルの操作 |
| 左パネル | オブジェクトの確認。特にレイヤータブ（一覧・重なり順）をよく使う |
| 右パネル | オブジェクトの編集。主にデザインタブを使う |

- **フレーム**：デザインを描く「紙」。フレーム上に置いたものが最終的に画像になる。スマホ・タブレット・デスクトップ用のサイズが用意されている

## 基本ツール
| ツール | キー | 使い方 |
| --- | --- | --- |
| 移動（選択） | `V` | 要素の選択・移動。Shiftを押しながら動かすと直線的に動く |
| フレーム | `F` | 右パネルからサイズを選んでフレームを作る |
| 長方形 | `R` | ドラッグで作成。Shiftを押しながらで正方形 |
| テキスト | `T` | クリックして文字を入力する。`Esc`で入力を終えると、テキスト全体が選択された状態になる |
| スポイト | `I` | 他の要素と同じ色にする |

- 操作の基本は「要素の作成・選択」「プロパティの変更」「配置」の3つ
- ツールの持ち替えはショートカットキーで効率化する
- 大きさや位置は、ドラッグで合わせるより右パネルに数値を入れる方が正確
    - `W`（横幅）・`H`（高さ）：例）ヘッダーの土台ならフレームと同じ375
    - `X`・`Y`（位置）：フレームの左上が X:0 / Y:0

## よく使う操作
| 操作 | Mac | Windows |
| --- | --- | --- |
| コピー＆ペースト | `command + C` → `command + V` | `ctrl + C` → `ctrl + V` |
| 複製 | `command + D`、またはoptionを押しながらドラッグ | `ctrl + D`、またはaltを押しながらドラッグ |
| 複数選択 | shiftを押しながらクリック | shiftを押しながらクリック |
| グループ化 | `command + G` | `ctrl + G` |
| グループ解除 | `command + shift + G` | `ctrl + shift + G` |
| 名前の変更 | `command + R` | `ctrl + R` |
| ロック | `command + shift + L` | `ctrl + shift + L` |
| 表示/非表示 | `command + shift + H` | `ctrl + shift + H` |
| 画像の配置 | `command + shift + K` | `ctrl + shift + K` |
| 要素間の距離を測る | 選択してoptionを押しながらカーソルを合わせる | 選択してaltを押しながらカーソルを合わせる |
| 水平方向の中央揃え | `option + V` | `alt + V` |
| 垂直方向の中央揃え | `option + H` | `alt + H` |
| 太字 | `command + B` | `ctrl + B` |
| ガイドラインの表示/非表示 | `shift + R` | `shift + R` |

- 矢印キーで微調整できる（1px単位。Shiftを押しながらだと10px単位）
    - 移動の単位は設定で8pxに変えられる（📎[ナッジ機能：移動の単位を変更する方法](https://bamka.info/figma-nudge/)）
- option / alt を押しながらドラッグして複製するとき、Shiftも一緒に押すとまっすぐ移動できる
- 同じ形を並べるときは、1つ作って複製する方が太さや長さがそろう（例：ハンバーガーメニューの線3本）
- ヘルプにショートカット一覧がないときは、画面右下の「？」の中から確認できる

## テキストの設定
テキストを選択すると、右パネルに「テキスト」の項目が出る。ここでフォント・サイズ・行間・字間を設定する。

| 項目 | 入力のしかた |
| --- | --- |
| フォント | フォント名をクリックして名前を入力すると検索できる（例：Noto Sans JP） |
| 行間（line-height） | 1.8 なら「180%」と入力する。数字だけだとpx指定になるので`%`をつける |
| 字間（letter-spacing） | 0.1em なら「10」と入力する（Figmaでは10%として扱われる） |

- Noto Sans JP はGoogleフォントなので、Figma上でインストールなしで使える
- 行間の入力欄では計算式も使える（例：フォントサイズ × 1.8）
- よく使う組み合わせはテキストスタイルとして登録できる（例：「セクション見出し」＝フォントサイズ20・行間180%）。色も同じような方法で登録できる

## レイヤーの操作
| 操作 | Mac | Windows |
| --- | --- | --- |
| 最前面へ | `]` | `]` |
| 1つ前面へ | `command + ]` | `ctrl + ]` |
| 1つ背面へ | `command + [` | `ctrl + [` |
| 最背面へ | `[` | `[` |

- レイヤーパネルは「上にあるものほど手前に表示される」
- 要素はあとから作るほど手前に重なる。背景の長方形はテキストなどを隠すので、`[`で最背面に送る
- ショートカットが効かないときは、レイヤーパネル上でドラッグして並び替えてもよい
- `[` はキーボードの「P」の右あたりにある。日本語入力がオンだと効かないことがあるので、英数入力に切り替えてから押す
- グループやレイヤーの名前は、レイヤーパネルでダブルクリックすると変えられる。中身が分かる名前にしておくと探しやすい（「レイヤー名の付け方」参照）

## コンポーネント
- ボタンやカードなど、何度も使うパーツを「ひな形」として登録する機能
- 作り方：グループ化 → コンポーネント化（Mac：`option + command + K`／Windows：`ctrl + alt + K`）
- レイヤーパネルのアイコンが紫色のひし形に変われば、コンポーネント化できている

| 用語 | 意味 |
| --- | --- |
| メインコンポーネント | 最初に作ったひな形 |
| インスタンス | メインコンポーネントからコピーしたもの |

- メインコンポーネントの色や文字の大きさを変えると、インスタンスにも反映される。1か所直すだけで全部そろう
- 同じパーツを複数並べるときの作り方
    1. 1つだけ作り込む
    2. コンポーネントにする
    3. コピーして必要な数に増やす
    4. オートレイアウトでまとめて間隔をそろえる
- 別々に作ると、あとで修正するときに同じ作業を何回もすることになる

## オートレイアウト
- 要素の大きさや数に応じて変わるフレーム（枠）を作ったり、要素の並び替えを簡単にしたりする機能
- 同じ見た目の要素が並ぶとき、グリッド状のデザインを作るときに便利
- 追加：まとめたい要素をすべて選択し、次のどれかで適用する
    - 右パネルのオートレイアウトのアイコンをクリック（もう一度クリックで解除）
    - 右クリック →「オートレイアウトの追加」
    - ショートカット `shift + A`
- 適用すると、要素は「Frame」というボックスになる

| 設定項目 | 意味 |
| --- | --- |
| 方向 | 並べる向き（初期値は横並び） |
| 間隔 | 並べた要素同士の余白 |
| パディング | フレームの上下左右の余白（初期値は10px） |
| 配置 | 上下左右のどこに寄せるか |

- テキストを変えると、中身の大きさに合わせてフレームのサイズも変わる
- ボタンの文字を真ん中にそろえるとき：土台の長方形とテキストを選択 → オートレイアウトを適用 →「水平方向の中央揃え」「垂直方向の中央揃え」を押す。目で合わせるより正確

## 便利機能
| 機能 | 内容 | ショートカット（Mac / Windows） |
| --- | --- | --- |
| ガイド | ドラッグ中に配置の目安が表示される。余白を数値で確認できる | 選択して`option` / `alt` で余白を表示 |
| グリッドレイアウト | フレーム上に補助線（マス目）を表示する | `shift + G`（表示/非表示） |
| オートレイアウト | 余白を数値で指定して配置する（上の「オートレイアウト」参照） | `shift + A` |
| アセット | よく使うパーツ（コンポーネント）を登録・管理し、呼び出す | `option + 2` / `alt + 2` |
| プロトタイプ | ページ遷移やアニメーションを設定し、プレビューできる | 実行：`option + command + Enter` / `alt + ctrl + Enter`<br>タブを開く：`option + 9` / `alt + 9` |
| 共有機能 | 複数人での共同編集、デザイン上へのコメント | ― |

### ガイド
- 整列や余白の調節を簡単にする機能
- 余白を1px単位で調節するときに使う

### グリッドレイアウト
- マス目の大きさを統一すると、複数のデザイナーが同じ余白間隔で作れる
- Webデザインでは8pxのグリッドが一般的（ZeroPlusの教材も8pxがルール）

### アセット
- 左パネルのアセットタブで、コンポーネントを管理する
- ヘッダー・フッター・ボタンなど、何度も使うパーツを登録する
- コンポーネントは一括で編集できる（例：ボタンの色をまとめて変える）

### プロトタイプ
- 例：ボタンをクリックしたら、お問い合わせページへ遷移させる
- デザイナー同士やエンジニアと、サイトの仕様を共有しやすくなる
- 今は機能があることを知っておけばよい（今後のレッスンで学ぶ）

### 共有機能
- Figmaの一番の魅力とされる機能
- 共同編集：「Team」を作ってメンバーを招待すると、Team内のファイルを複数人で編集できる（作れるファイル数は料金プランで変わる）
- コメント：デザインファイル上にコメントを残せる。デザイナー・エンジニア間のやり取りが円滑になる

## 見本画像を読み込んでロックする
1. フォルダとFigmaを並べ、画像をFigmaの空いているところへドラッグ&ドロップする
2. 横幅をフレームに合わせる（SPなら375px）
3. 動かないようにロックする
- 見本はフレームの隣に置き、テキストは「原稿」からコピペすると作業しやすい
- .figファイルは、Figmaにドラッグ&ドロップするか、ホームの「ファイルをインポート」から読み込める

# デザインルールの例
授業のデザインで決められていたルール。余白は「グループが大きいほど広く」なっている（近接）。

| 項目 | 値 |
| --- | --- |
| フォント | Noto Sans JP |
| コンテンツの幅 | 343px（375pxの画面で左右16pxずつ空ける） |
| セクション間 | 160px（上80px・下80px） |
| セクション内の兄弟要素 | 64px |
| グループ内の兄弟要素 | 40px |
| 近接が必要な要素 | 8〜32px |
| line-height | 1.8 |
| letter-spacing | 0.1em（Figmaでは10） |

- **コンテンツの幅**：画面幅375pxから左右に16pxずつ余白をとった幅。テキストや画像はこの中におさめる
    - 375 − 16 − 16 = 343
- **セクション間**：各セクションの上下に80pxずつ余白をとるので、セクションが並ぶと 80 + 80 = 160px になる
- **兄弟要素**：同じ階層に並んでいる要素同士のこと（例：同じセクション内の「見出し」と「カードの一覧」）

| 余白の種類 | 例 |
| --- | --- |
| セクション内の兄弟要素（64px） | セクションタイトルとセクションの中身の間 |
| グループ内の兄弟要素（40px） | カード同士の間 |
| 近接が必要な要素（8〜32px） | 見出しとその説明文の間 |

- 慣れるまでは、このルールを基本にして自分のポートフォリオのワイヤーフレームを作ってもよい

# レイヤー名の付け方
正解はないが、「誰が見ても中身や役割が想像できる」名前にする。

| ルール | 例 |
| --- | --- |
| 「ページ略称-要素」にする | `top-kv`、`top-works` |
| 子要素はページ略称を省略する | `top-kv` の中は `kv-copy`、`kv-bg` |
| 同じ役割の繰り返し要素は同名にする | `hamburger-bar` × 3 |
| まとめ役には `-list` をつける | `article-list` の中に `article` × 3 |
| 日英のテキストは `_jp` / `_en` で区別する | `section-heading_jp`、`section-heading_en` |
| アイコンは `icon-〇〇` にする | `icon-mail`、`icon-tel` |

```
top-kv          ← セクション
└ kv-copy       ← 子要素は "top-" を省略
└ kv-bg
```

# 【発展】オートレイアウト・コンポーネントの応用
| 機能 | 内容 |
| --- | --- |
| 横幅が広がるボタン | オートレイアウトで、文字量に応じて横幅が自動で広がる |
| 横幅が固定のボタン | 文字量に関わらず幅を一定にする。横並びで揃えたいとき、クリック領域を一定にしたいときに使う |
| バリアント | 種類・サイズ・状態などが少し違うコンポーネントを1つにまとめて管理する |
| Wrap（折り返し） | オートレイアウトで、幅に応じてカードを折り返す（CSSの`flex-wrap: wrap;`に近い） |

バリアントの考え方
```
Button（コンポーネントセット）
 ├ プロパティ「Type」  → Primary / Secondary
 ├ プロパティ「Size」  → Large / Medium / Small
 └ プロパティ「State」 → Default / Hover / Disabled
```
- 最小幅・最大幅を設定すると、CSSの`min-width`/`max-width`のように1行あたりの枚数を調整できる

# デザイン制作のチェックリスト
## 制作の進め方
- デザインを作る前に、必ず要件定義をする（[[上流工程]]参照）。フィードバック依頼には要件定義書を添付する
- フィードバックは、全部作り終えてからではなく、こまめにもらう
    1. 要件定義書
    2. ラフスケッチ
    3. ワイヤーフレーム
    4. デザインカンプ（トップページが80%くらいできたとき）
    5. 修正したデザインカンプ（「修正 → フィードバック」を繰り返す）
- フィードバックを受けて直すときは、フレームごと複製してすぐ横に貼り、修正前を残して新しい方を直す（Before/Afterが分かるように）。返信やメモはFigmaのコメント機能で残す
- フィードバック依頼の前に、Figmaの共有設定を「コメントモード」にしてURLを共有する（📎 [Figmaの共有モード](https://zero-plus.io/media/l_web-design/figma_sharing_mode/)）

## Figmaの操作のコツ
- 新規ファイルは「デザイン（Design）」から作る。「FigJamボード」はホワイトボード用なので使わない
- キャンバスの移動：マウスは`Space`＋ドラッグ、トラックパッドは2本指でスライド
- ズーム：`command`/`ctrl`＋ホイール、トラックパッドは2本指で広げる・つまむ

| 操作 | Mac | Windows |
| --- | --- | --- |
| 取り消し／やり直し | `command + Z`／`command + shift + Z` | `ctrl + Z`／`ctrl + shift + Z` |
| グループ内の要素を直接選択 | `command`＋クリック | `ctrl`＋クリック |
| 中身はそのままで枠だけサイズ変更 | `command`＋ドラッグ | `ctrl`＋ドラッグ |
| 縦横の位置を保ったまま複製 | `shift + option`＋ドラッグ | `shift + alt`＋ドラッグ |

## ワイヤーフレームのチェック
- [ ] 大枠は「長方形」ではなく**フレーム**（`F`）で作る。レイヤーパネルで「#」になっていればフレーム
- [ ] ガイド線を引く（`shift + R`でルーラーを表示し、引っ張り出す）
    - PC：コンテンツ最大幅（教材は800px・960px・1080px）の長方形を中央に置き、両端に線を引いて長方形を消す
    - SP：幅16pxの長方形を両端に置き、内側に線を引いて長方形を消す
- [ ] スタイルガイドを先に作る（カラー、フォント、基本のフォントサイズ、コンテンツ最大幅、余白）
- [ ] ページごとに「左にSP・右にPC」で横に並べる（SPをまとめて左、PCをまとめて右、ではない）
- [ ] レイヤーを整理し、名前をつける（「Rectangle 1」だらけにしない）
- [ ] 整列ツールで要素を揃える（目分量で置かない。📎 [Figmaで整列・均等配置する方法](https://wentz-design.com/post/figma-how-to-use-alignment/)）。オートレイアウトは慣れないうちは無理に使わなくてよい
- [ ] テキストボックスを段落ごと・役割ごと（見出し・本文・注釈）に分ける。改行で余白をとらない。あえて改行したい場所以外は改行しない（画面幅で折り返し位置が変わるため）
- [ ] フォントサイズ：本文は16px（若者向けのSPなら14pxも可）、注釈・日付などは12px、絶対的な最小は10px（「※当社比」など）
- [ ] サイズや余白は8の倍数で考える。少なくとも偶数にし（13px・21pxなどは避ける）、微調整は4の倍数
- [ ] 行間は180%〜220%（狭いと窮屈、広いとまとまりが散漫になる）
- [ ] 余白：セクション上下はまず120px。窮屈なら要素の内側の余白を、近すぎるなら要素間の余白を調整する（余白も立派な情報）
- [ ] デザイン四原則が守れているか。対比は中途半端な差ではなく、思い切って差をつける
- [ ] フォントは最大2〜3種類（日本語1つ＋英数字1つで十分）
- [ ] 角丸の値を統一する

## デザインカンプのチェック
- [ ] 守破離の「守」：参考サイトのスクショをフレームの横に貼り、見比べながら作る
- [ ] サイト全体ではなく、パーツごとに真似する（ボタンの形・色・影、セクションタイトルの装飾、画像と文字の配置、配色）（📎 [徹底的にマネをするデザインの技術](https://bluemoondesign.jp/design/design-example2)）
- [ ] ヘッダー・フッター・ボタン・CTAなどはコンポーネント化しておく（📎 [Figmaのコンポーネント機能](https://zero-plus.io/media/l_web-design/figma_component/)）
- [ ] 背景色と文字色のコントラストをツールで確認する（📎 [Colorbase コントラストチェッカー](https://colorbase.app/ja/tools/contrast-checker)）
