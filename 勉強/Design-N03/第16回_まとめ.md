# 要件定義（予習）
- 「何をどうやって作るのか」を決めること。Webサイト制作では、必要なコンテンツや機能をまとめる
- 全工程の土台なので、最も大切な工程（詳しくは[[上流工程]]参照）

## 決める項目
| 項目 | 例 |
| --- | --- |
| 目的 | 就職・転職活動、案件獲得 |
| サイトの種類 | ポートフォリオサイト、ブログサイト |
| ターゲット（一番見せたい人） | 企業の人事、クラウドソーシングの発注者 |
| 載せたいコンテンツ | 自己紹介、制作実績一覧、制作物の個別解説（**載せる理由**も考える） |
| 優先順位 | ターゲットに響くものから選ぶ |
| ページ構成（サイトマップ） | 必要なページを書き出してページ数を把握し、デザインの作業量を見積もる |
| デザインの方向性 | 参考サイトを探して決める |

- 目的を決めないと、コンテンツもデザインも方向性が定まらない
- ターゲットを決めておくと、コンテンツを考えやすくなる
- 一見使わないと思う内容も案として出しておく（あとで追加できるように）
- 進め方：コンテンツ案をとにかく出す → 優先順位をつける → 優先順位の高いものをデザインに落とし込む

# お問い合わせフォームのデザイン
## お問い合わせフォームとは
- Webサイトを見た人からお問い合わせをもらうために設置するWebフォーム
- 「お問い合わせ」はWebサイトのゴールの1つ。だから使いやすさが大切（項目が多い・分かりにくいと離脱される）

## デザインのポイント
| ポイント | 理由・やり方 |
| --- | --- |
| 入力項目を絞る | 任意項目はできるだけ減らし、必須項目だけにする。必須も多すぎると手間が増える。「本当に今その情報が必要か」を確認する |
| 見出しと入力欄は**縦**に並べる | 横並びより視線の動きが少なく、迷わない |
| 入力項目も縦に並べる | 上から順に入力できる |
| 項目ごとに余白をあける | 情報のまとまりが分かる（近接） |
| 選ぶ数に合わせて入力欄を選ぶ | 1つだけ選ぶか、複数選べるかで変える |
| 入力の手間を考える | プルダウンは2クリック、ラジオボタンは1クリックで済む |
| 入力例は欄外に書く | プレースホルダー（欄の中の薄い文字）だと、入力を始めると消えてしまう |
| 必須項目は「必須」と書く | 「※」や「*」は意図が伝わりにくいことがある |
| プライバシーポリシーの同意チェックをつける | 氏名やメールアドレスなどの個人情報を扱うため |
| ボタンは送信ボタンだけにする | 「キャンセル」などは不要。他のページへのリンクも減らす |
| 送信ボタンの文字を具体的にする | 「送信」「次へ」ではなく、「確認ページへ移動する」「メッセージを送信する」のように次の動作が分かる言葉にする |

- 📎 [使いやすいお問い合わせフォームをデザインしよう](https://zero-plus.io/media/l_web-design/contact-form/)

## 授業でのお題（SP版を作る）
入れる項目：会社名、お名前、メールアドレス、お問い合わせ項目（Webサイト制作／DTP制作／写真撮影／PR映像制作／その他）、お問い合わせ内容、プライバシーポリシーの同意チェックボックス、送信ボタン

- どこを必須項目にするかも自分で考える
- 自分で参考サイトを見つけて、まず作ってみる

作るときのポイント
- 繰り返し使う要素はコンポーネント化する
- ユーザーが入力しやすい工夫を考える（キーワード：UIデザイン）
    - プライバシーポリシーの扱い
    - ユーザーの導線
    - 入力内容に合った入力欄を選ぶ

# UI（User Interface）
- 「入力できそう」「進めそう」「押せそう」のように、ユーザーが次の行動をイメージできる見た目にする
- 使っていて迷わないことが、良いUI
- デザインは一日にしてならず。失敗を恐れず、インプットとアウトプットを繰り返して磨く

# プライバシーポリシー
- 個人情報をどう扱うかをユーザーに伝えるもの。Webサイトを公開するときは設置がとても大切
- ポートフォリオや成果物に置いておくと、信頼感が上がる
- 授業で配布された雛形をベースに、自分のサイトに合わせて調整する（📎 [プライバシーポリシーの雛形](https://docs.google.com/document/d/1YaD-cLuCpaI0jBJrhzWjyYG6d-QsUkgbtm9xF0mvYEo/edit?tab=t.gx6fx1mop4y7)）
