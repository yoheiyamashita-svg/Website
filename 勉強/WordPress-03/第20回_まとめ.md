# 固定ページ
## 固定ページとは
- 名前の通り「メニューなどに固定して使うページ」
- 例：個人ブログの「著者プロフィール」「このブログについて」「プライバシーポリシー」、企業サイトの「会社概要」「お問い合わせ」

| | 投稿 | 固定ページ |
| --- | --- | --- |
| 順番 | 日付順などの順番がある | 独立している |
| 前後のリンク | 「前の記事」「次の記事」がある | ない |
| 使う場所 | ブログ記事など | トップ、会社概要、お問い合わせなど |

## 固定ページの使い方は2通り
| 使い方 | ファイル | 内容 |
| --- | --- | --- |
| 独立したページのテンプレートとして使う | `page.php` | 管理画面から書く想定のページ。全部を動的にする（`single.php`に近い感覚） |
| 独自の構造のページとして使う | `page-〇〇.php` | PHPファイルに直接文章や画像を書き、静的なコードを残したまま部分的に動的にする（**教材はこちら**） |

## 作り方
1. 管理画面の「固定ページ」→「新規追加」で作る
2. 「URL」（パーマリンク）のスラッグを半角英数字で入れる（例：サービス＝`service`、私たちについて＝`about`、お問い合わせ＝`contact`、プライバシーポリシー＝`privacy`）。全角は悪影響が出る
3. 「公開」を押す
4. テーマに`page-スラッグ.php`を作る（例：`page-service.php`）

- スラッグを入れることで、固定ページを自在に扱える
- 事例ページはカスタム投稿で作るので、固定ページにはしない

テンプレート階層（上ほど優先）
1. `$customname.php`
2. `page-$slug.php`（例：`page-company.php`）
3. `page-$id.php`（例：`page-10.php`）
4. `page.php`

```php
<!-- 固定ページへのリンク -->
<a href="<?php echo esc_url(home_url('/service')); ?>">サービス</a>
```
- 📎 [固定ページを作成しよう](https://zero-plus.io/media/l_wordpress/pages/)／[ブログサイトをWordPress化しよう 固定ページ編](https://zero-plus.io/media/l_wordpress/html-to-wordpress-pages/)

## 固定ページのテンプレート化
1. `〇〇.html`を`page-〇〇.php`に移す
2. ヘッダー・フッターを読み込む（トップページで作ったものを使う）
3. 下層ページのKVを`m_kv.php`、CTAを`cta.php`として作り、`get_template_part()`で読み込む
4. リンク・画像のパスを書き換える
5. メインループを書く

固定ページでもメインループを書く理由
- メインループの`the_post();`は、WordPressが「今のページのデータ」を使えるように準備する処理
- これがないと、`the_title()`・`the_content()`・`get_the_ID()`などが正しく動かない
- `page-〇〇.php`自体では使っていなくても、中で呼び出している`m_kv.php`で使っていれば必要

# ページに合わせて表示を出し分ける
`m_kv.php`のタイトルや説明文を、条件分岐でページごとに変える。

```php
<?php if (is_page('about')) : ?>
  <!-- 「私たちについて」ページのとき -->
<?php elseif (is_post_type_archive('case')) : ?>
  <!-- 事例の一覧ページのとき -->
<?php elseif (is_singular('case')) : ?>
  <!-- 事例の個別ページのとき -->
<?php elseif (is_404()) : ?>
  <!-- 404ページのとき -->
<?php else : ?>
  <!-- どれにも当てはまらないとき -->
<?php endif; ?>
```

| 関数 | trueになるページ |
| --- | --- |
| `is_page('スラッグ')` | その固定ページ |
| `is_post_type_archive('スラッグ')` | そのカスタム投稿の一覧ページ |
| `is_singular('post')` / `is_singular('case')` | 通常の投稿／そのカスタム投稿の個別ページ |
| `is_404()` | 404ページ |

| 論理演算子 | 意味 |
| --- | --- |
| `条件A \|\| 条件B` | または（どちらかがtrue） |
| `条件A && 条件B` | かつ（両方がtrue） |

- ヘッダーロゴを、トップページでは`h1`、それ以外では`p`にする出し分けも、同じ考え方でできる

# CSS・JSを読み込むページを限定する
## CSS
- `swiper-bundle.min.css`を`wp_register_style()`で登録しておく
- 条件分岐で、`corporate.css`を読み込むページ（トップ・各固定ページ・404など）を指定する
- 依存先に`reset.css`・`swiper-bundle.min.css`を指定し、先に読み込ませる
- `.m_kv`と`.top_kv`は間違えやすいので注意

## JavaScript
```php
// ライブラリは登録だけしておく
wp_register_script('swiper_script', get_template_directory_uri() . '/js/swiper-bundle.min.js', array(), '1.0');

// main.jsは、ライブラリを先に読み込んでから読み込む
wp_enqueue_script(
  'main_script',                                   // 識別名
  get_template_directory_uri() . '/js/main.js',    // パス
  array('swiper_script'),                          // 先に読み込むスクリプト
  '1.0',                                           // バージョン
  true                                             // trueで</body>の直前に出力
);
```

| 引数 | 意味 |
| --- | --- |
| 1つ目 | 識別名 |
| 2つ目 | スクリプトのURL（CDNのURLもそのまま指定できる） |
| 3つ目 | 先に読み込むスクリプトの配列（依存関係） |
| 4つ目 | バージョン（キャッシュ対策） |
| 5つ目 | `true`で`</body>`の直前に出力 |

- 教材では`swiper-bundle.min.js`・`gsap.min.js`・`ScrollTrigger.min.js`を登録し、`main.js`の依存先にする
- Webフォント・CSS・JSは、すべて`functions.php`にまとめて読み込む

## defer属性をつける
`wp_enqueue_script()`だけではdeferをつけられないので、フィルターを使う。
```php
add_filter('script_loader_tag', 'add_defer', 10, 2);
function add_defer($tag, $handle) {
  // 識別名がmain_script以外は、そのまま返す
  if ($handle !== 'main_script') {
    return $tag;
  }
  // src= の前に defer を入れて返す
  return str_replace(' src=', ' defer src=', $tag);
}
```
- deferはメインのスクリプトにだけつければよい。`'main_script'`は読み込んだときの識別名と合わせる
- 📎 [WordPressでスクリプトを読み込もう](https://zero-plus.io/media/l_wordpress/enqueue-script/)

# カスタムフィールド
## カスタムフィールドとは
- 固定ページや投稿に、標準のタイトル・本文以外の入力項目を追加できる機能
- メリット：入力作業の効率化、表記の統一、管理画面からテキストなどを修正できる

| 実装方法 | 特徴 |
| --- | --- |
| WordPressの標準機能 | 元の状態では単純なテキストしか扱えない |
| `functions.php`にコードを書く | カスタマイズの幅は広いが、難しい |
| プラグインを使う | 標準より幅が広く、難易度も低い。バランスが良い（Advanced Custom Fields、Custom Field Suite など） |

## Advanced Custom Fields（ACF）の使い方
1. プラグイン「Advanced Custom Fields」をインストールして有効化する
2. 「ACF」→「フィールドグループ」→「新規追加」
3. フィールドを作る（例：質問1＝テキスト／`question_1`、回答1＝テキストエリア／`answer_1`）。こまめに保存し、「並び替え」「複製」を使うと早い
4. 「このフィールドグループを表示する条件」を「固定ページ」「等しい」「サービス」にする
5. 固定ページの編集画面に入力欄が出るので、値を入れる

## テンプレートで呼び出す
```php
<?php if (get_field('question_1')) : ?>
  <!-- 値が入っているときだけ表示する -->
  <p><?php echo get_field('question_1'); ?></p>
  <p><?php echo get_field('answer_1'); ?></p>
<?php endif; ?>
```
- `get_field('フィールド名')`で値を取得する
- 質問ごとに、`elseif`ではなく単独の`if`を並べる

# カスタム投稿
## カスタム投稿とは
- デフォルトの「投稿」とは別に、オリジナルの投稿機能を追加できる
- 例：ブログ ← デフォルトの投稿、お知らせ・制作実績・スタッフ紹介 ← カスタム投稿
- 実装方法：`functions.php`にコードを書く、またはプラグインを使う

## Custom Post Type UIの使い方
1. プラグイン「Custom Post Type UI」をインストールして有効化する（英語なら「ダッシュボード」→「更新」→「翻訳を更新」）
2. 「CPT UI」→「投稿タイプの追加と編集」
3. 投稿タイプスラッグ：`case`、ラベル：事例、「アーカイブあり」を`true`にして追加する
4. 左のメニューに「事例」ができるので、投稿を2つ以上作る

| ファイル | 役割 |
| --- | --- |
| `archive-case.php` | 事例の一覧ページ |
| `single-case.php` | 事例の個別ページ |

## 一覧ページ（archive-case.php）
```php
<!-- カスタム投稿の一覧ページへのリンク -->
<a href="<?php echo get_post_type_archive_link('case'); ?>">事例</a>

<!-- ループの中で：何番目の投稿か（0から数えるので+1） -->
<?php echo $wp_query->current_post + 1; ?>
```
- メインループで、リンク（`the_permalink()`）・サムネイル（`the_post_thumbnail()`）・タイトル（`the_title()`）を動的にする
- 本文が長いときは、200文字を超えたら「…」で省略する（📎 [タイトルと本文の文字数制限](https://www.m-hand.co.jp/blog/program/5130/)）
```php
<?php
if (mb_strlen($post->post_content, 'UTF-8') > 200) {
  // 200文字を超えたら、タグを除いて200文字で切り、…をつける
  $content = str_replace('\n', '', mb_substr(strip_tags($post->post_content), 0, 200, 'UTF-8'));
  echo $content . '…';
} else {
  echo str_replace('\n', '', strip_tags($post->post_content));
}
?>
```

## 個別ページ（single-case.php）
- メインループで、サムネイル・タイトル・本文（`the_content()`）を動的にする
- CSS・JSの読み込みの条件分岐に、一覧ページ・個別ページを追加する

## カテゴリー・タグ・カスタムタクソノミー
- カテゴリーは投稿を分類する「フォルダ」、タグは記事に貼る「付箋」のイメージ（📎 [カテゴリーとタグの違い](https://webst8.com/blog/wordpress-category-tag/)）
- カスタム投稿のカテゴリーやタグは「カスタムタクソノミー」と呼ぶ。Custom Post Type UIで作れる（📎 [カスタムタクソノミーとは](https://webst8.com/blog/wordpress-custom-taxonomy/)）
- 【卒業後】カスタム投稿は`functions.php`でも追加できる（📎 [functions.phpでカスタム投稿とカスタムタクソノミーを作る](https://wordpress-web.and-ha.com/summary-add-custom-post-type/)）。`functions.php`は重要なファイルなので、作業前にバックアップをとる

# 作業を速くする工夫
- よく書くPHPのコード（インクルードタグ、リンク、ループ内のテンプレートタグなど）はスニペットに登録する。`php.json`だと`<?php ?>`の中でしか使えないので、`html.json`に書く
- CSS・スクリプトの読み込みなど毎回出てくるコードは、Notionなどにストックしておき、コピペして書き換える
