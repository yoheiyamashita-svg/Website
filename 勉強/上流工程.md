# はじめに
##  UX/UIデザイナーの責任・役割
- UX/UIデザイナーは、製品やサービスの使用におけるユーザーの体験（UX）と、そのインターフェース（UI）を設計・最適化する専門家。
- プロダクトの設計フェーズからリリースまでの多くのステップに関与
    - ユーザーニーズの調査
    - ユーザーフローやワイヤーフレームの作成
    - 視覚デザインの策定など、
- 良好なUX/UIデザインは、製品の成功を左右するため、デザイナーはユーザーテストやフィードバックを元に改善を続ける必要がある。
- その過程で、エンジニアやプロダクトマネージャーと連携し、ユーザーの期待に応える製品を実現するためのブリッジとしての役割も果たす。

## UX/UIデザイナーに必要とされるスキル？

- ユーザー・市場の調査、理解をすること
- 製品・サービスの価値発見をすること
- 製品・サービスの設計ができること

# デザインとは
- 目的を設定し、計画を立て、仕様として表現するまでの一連のプロセス
- 「アートは自己表現、デザインは課題解決の手段」と言われる
- Webサイトは「売り上げを伸ばしたい」「集客したい」などの目的を達成するための手段の1つ。そのため、問題を整理し、調査・分析して設計し、それを表現に落とし込む
- 見た目を作る前の**設計**からがデザイン。設計がしっかりしていると、意図と説得力のあるデザインになる

## 例：iPhoneの設計
| 段階 | やること | iPhoneの例 |
| --- | --- | --- |
| 調査 | 人々に何が必要とされているか調べる | 「お」を入力するのにボタンを5回押すのが大変／画面が小さく見えにくい |
| 分析 | どこを改善すべきか考える | テキスト送信が多い時代、入力を楽にできないか／本体全体を画面にできないか |
| 価値発見 | 新しい価値を生み出す | フリック入力、タッチスクリーン |

## 上流工程と下流工程
| 工程 | 内容 |
| --- | --- |
| 上流工程 | デザインの設計。サイトで何を達成したいか、ユーザーが何を求めているかを調査・分析し、情報を準備する |
| 下流工程 | 設計をもとに、Figmaなどで見た目を作る |

上流工程の流れ：**調査・分析 → 価値発見 → 要件定義**

- デザインは範囲が広く、それぞれが専門職になるほど。一気に覚える必要はないが、少しずつ学び続けて市場価値を上げる
- どの業界でも、上流の「設計」から請け負える人は市場価値が高い
- デザインには「マーケティング」「ディレクション」「クリエイティブ」なども含まれる。全部できるほど単価が上がりやすい。全部を広く学ぶか、1つを深めるかは自分に合うスタイルを選ぶ

# 調査
## ユーザー調査
- ユーザー：そのサービスを使う人、商品を買う人（例：アプリならダウンロードして使う人、カフェなら来店して飲食する人）
- ユーザーが何を考えているか分からないと、何を求めているかも分からない
    - 例：カフェオーナーはサンドイッチを推したいが、ユーザーは「ボリュームが多すぎて食べにくい、コーヒーが美味しい」と考えていた → コーヒーを強化した方が集客につながるかもしれない
- **ユーザーファースト**：企業が伝えたいことではなく、ユーザーが何を求めてサイトに来るかを第一に考える
    - 作る側の都合で作ると、ユーザーは目的の情報を見つけられずに離れてしまう（例：求人を見たいのに企業情報ばかりで求人ページが見つからない）
- 手法：インタビュー、アンケートなど（授業後アンケートもユーザー調査の1つ）。実際のユーザーがいない場合は、架空のペルソナやカスタマージャーニーを作る
- Web制作との関係：誰が（ターゲット）、何を解決したくて（目的）、どのタイミングで（経路）サイトに来るかを想定して設計する
    - 失敗例：ポートフォリオに「HTML/CSSできます！」と自分の伝えたいことだけ書く → クライアントには何がすごいのか伝わらない
- ユーザーは**自分の想像の範囲でしか**欲しいものを言えない
    - 「速い馬が欲しい」と言った人の本当の目的は「速く移動すること」。言葉をそのまま鵜呑みにせず、本質を見抜く

## 市場調査
- 市場：物事が売り買いされる場所（例：ZeroPlusならプログラミングスクール市場）
- 同じユーザーをターゲットにしている他社が、どんな戦略・サービスを出しているかを調べる（スポーツで相手を分析してから試合に臨むのと同じ）
- **競合（ライバル）調査**：ライバルがサイトでどんな言葉や見せ方を使っているかを見て、良い点は真似し、差別化できる点を探す
    - フリーランスWeb制作者のライバルは、同業フリーランスとWeb制作会社。クオリティが安定している「検索上位のWeb制作会社」を参考にする（例：「Web制作会社 東京」で検索）
    - 最初は質より量。20〜30社見ると共通点が見え、サイトに仕込まれた戦略に気づけるようになる
    - 参考サイトが見つけにくい業種（小さな飲食店など）は、Googleマップで「カフェ」と検索して店舗情報のURLからたどる、「おすすめ〇選」の記事から探す。AIに架空のライバルを出してもらう場合は、事実か自分で確かめる
    - 実務では、スプレッドシートやNotionなど使いやすいツールで自分なりのフォーマットを作る

# 分析
- 調査と分析は、ほぼ同時に行うことが多い
- 集めただけの情報は「ただの情報」。分析することで「意味のある情報」になる（量で集めた情報の質を高める工程）
- 分析すること自体が目的にならないよう、何のために調べているかを常に振り返る
- **ヒートマップ**：サイトのどの部分が一番見られているかなどが分かる手法

## SWOT分析
| | プラス要因 | マイナス要因 |
| --- | --- | --- |
| 内部環境 | Strength（強み） | Weakness（弱み） |
| 外部環境 | Opportunity（機会） | Threat（脅威） |

例：フリーランスでWeb制作をする場合
- 強み：単価が安い、1人なのでコミュニケーションミスがない
- 弱み：実績が少ない
- 機会：コロナ禍でフリーランスに頼む顧客が増えた
- 脅威：コロナ禍でWeb制作者も増え、ライバルが増えた

AIを使って分析を深めるときのプロンプト例
```text
あなたはフリーのWeb制作者です。
以下の#サービス名のサービスのSWOT分析を行なってください。
出力は日本語かつ表形式で行なってください。
必要な情報があれば検索をしたり、以下のサービス情報から取得、逆にヒアリングをして情報を収集してください。

#サービス名
Webサイト制作サービス

#サービス情報
・フリーランスで1人でサービスを運営する想定
・担当範囲はデザインの上流工程からサーバーアップまで
・他の制作会社と比べて比較的安価に対応可能
・CMS化はWordPressで対応できる
・連絡は平日の日中や休日にも対応できる
```
- 「もっと詳細を出して」「各項目10個ずつ出して」「弱みを強みに変えるには？」などと会話して思考を深める

# 価値発見
- ユーザーが求めていないものは価値にならない（黒い服が欲しいのに、人気の白い服を売り込まれても響かない）
- 価値発見をする理由は「作るものの方向性をずらさないため」。チームで作るときは特に、方向性が決まっていないとサービス・デザイン・文章が少しずつずれる
- 流れ：調査（お客さんはどうしてる？）→ 分析 → 価値発見 → 価値の定義 → 価値を届けるための施策を考える

## デザイン思考とVUCA
- 以前は「仮説を立てて検証する」仮説検証型のビジネスが主流だった
- 今は**VUCA**（変動性・不確実性・複雑性・曖昧性）と言われる予測困難な時代なので、ユーザーの気持ちを読み取る「ユーザー中心のデザイン」の考え方が注目されている（デザイン思考）

## フレームワーク
- **フレームワーク**：問題を整理して解決方法を見つけるための考える枠組み。複雑な情報を見える化し、考え方の手順や方向性を示してくれる
- フレームワークを使うこと自体を目的にしない。状況に合わせて使い分ける
- 「自分の考え（主観）」と「調査から得た客観的な情報」を区別する

## バリュープロポジション
- 製品やサービスがユーザーに提供する価値を明確にしたもの
- 「自社が提供できる価値のうち、競合にはないもの」×「ユーザーが求めている価値」が重なる部分
    - 例：ZeroPlusの場合、スクール運営自体は他社にもあるが、「つよいコミュニティ」が独自の価値。それが「仲間とのつながりや継続的な学習環境」を求めるユーザーのニーズと重なる
- どの価値を重視するかをチームやクライアントと共有しておかないと、認識がずれる。完成後に「思っていたのと違う」とならないようにする

バリュープロポジションキャンバスの項目
| 側 | 項目 |
| --- | --- |
| 顧客（右の丸い表） | 顧客が実現したいこと、ゲイン（顧客の利益）、ペイン（顧客の悩み） |
| 自社（左の四角い表） | 製品・サービス、ゲインクリエイター（利益をもたらすもの）、ペインリリーバー（悩みを取り除くもの） |

- 顧客の属性から先に埋める。AIに上の6項目を表形式で出してもらい、協力してもらいながら埋めてもよい

# 要件定義
- Webサイトを作るときに、チームやクライアントと認識がずれないよう、必要事項を事前に決めて明確にしておくこと
- 上流工程の最後の工程で、下流工程（デザイン）への橋渡し役。曖昧だとデザインの軸がぶれ、下流工程が進まない
- どの現場でも使い、どの業界でも要件を定義できる力は高く評価される
- 仲の良い知人の案件でも必ず行う。口約束で始めると、コンテンツの追加要求や作り直しが起き、余計なやり取りや工数が増える
- 「言った・言っていない」のトラブルを防ぐため、決めたことは必ず要件定義書に書いて共有する
- 日常でも、引っ越し先選び（駅から徒歩何分、バストイレ別など）では自然と要件を決めている
- 項目：サイトの基本情報、ユーザーターゲット、コンテンツ要件、デザイン要件など
    - ユーザーターゲットの「ニーズと期待」は、カスタマージャーニーマップから持ってくる
    - 実務ではクライアントがマーケティングに詳しくないことが多いので、ペルソナなどは制作者がヒアリング・提案しながら埋める

## コンテンツ設計
サイトの中身を考える工程。
- 「大から小へ」：まず必要なセクション（大枠）を決め、次にセクションの中身（詳細）を決める
    - 例：アクセスセクション → Googleマップ、住所、電話番号、最寄り駅を載せる
    - 例：メニューセクション → ドリンク・フード・デザートでグループ分けし、画像・メニュー名・価格を載せる
- デザインは「分ける」：コンテンツ設計の段階では見た目は考えない。同時に考えると、デザイン重視になって目的からずれる
- **発散と収束**：前半は思いつく限りアイデアを出し（AIに頼ってもよい）、後半でユーザーが求めるものを基準に厳選する
    - 例：お知らせセクション → ユーザーは新作入荷の情報を期待している → タイトルは必須、サムネイルで目立たせる、最新順に並べる
- 情報が多いときは、グループ分けを考える（サイトマップの作り方を参考にする）

ポイント
1. 調査した情報や目的から考える。深掘りには**マンダラチャート**が便利（中央にサイトの一番の目的、周りに達成に必要な要素を8つ書き、さらにそれぞれを深掘りする）
2. ギャラリーサイトの構成やコンテンツを分析して、アイデアを周りから得る（📎 [Pinterest](https://jp.pinterest.com/)／[SANKOU!](https://sankoudesign.com/)／[Parts.](https://partsdesign.net/)）
3. 配置する順番もコンテンツ設計に含まれる。類似サイトを探して参考にする

## デザインシステム
- 制作するデザインのルールやコンポーネントの集合体
    - デザインのルール：使う色の一覧、セクション間の余白、画面の左右の余白など
    - コンポーネント（部品）：ボタン、セクションタイトルなど（CSS設計のモジュールに近い）
- ルールを決めておくと、デザインのバランスが崩れず、サイト全体に統一感が出る。コーディングもしやすくなる
    - コーディングの授業で使ったデザインデータにも「スタイルガイド」としてルールがあったので、CSS変数や`l_container`・`l_contents`にまとめられた
- 📎 [メルカリのデザインシステムへの取り組み](https://engineering.mercari.com/blog/entry/2019-08-26-090000/)／[デジタル庁デザインシステム](https://www.digital.go.jp/policies/servicedesign/designsystem)

# 下流工程に向けて
## 守・破・離
| 段階 | 意味 | Webデザインでは |
| --- | --- | --- |
| 守 | 型を忠実に守り繰り返す | プロがデザインしたサイトを真似て模写する |
| 破 | 自分なりの要素を加える | 模写ができたら、自分なりのアレンジを加える |
| 離 | 型から離れて独創性を追求する | 完全にオリジナルのデザインを作る |

- 「センスは場数」。最初からすごいデザインを作れる人はいないので、まず場数を踏む
- 模写するときは、📎 [GoFullPage](https://chromewebstore.google.com/detail/gofullpage-full-page-scre/fdpohaocaechififmbbbbbknoalclacl?hl=ja)でサイト全体を画像にしてFigmaに貼ると取り組みやすい（📎 [GoFullPageの使い方](https://ipponka.com/column/2386)）

## デザインの四大原則と色彩心理学
- 人が美しいと感じるレイアウト（黄金比など）や、色が人に与える影響は研究されている。色の働きを知っていれば、人を目的の方向へ誘導できる
- 📎 [デザインの四大原則](https://bulan.co/swings/design4principals)（近接・整列・強弱・反復）／[色彩心理学](https://blog.btrax.com/jp/color/)
- 配色は理由をつけて考える
    - 例：採用サイト → 青（誠実）、グレー（緊張感）
    - 例：老舗カフェ → 茶色（クラシック）、イタリアン → 赤（トマト料理）
- サンプルやテンプレートを活用する（📎 [UIキット](https://note.com/moqup_hei/n/n9016783dd2e2)／[テンプレート](https://digital-hacks.jp/blog/archives/11777)／[FigmaのUIキット](https://www.figma.com/community/file/890918667894765661)）
